# 智命（ZhiMing）· 智能体数字人生命模拟

> 项目名：智命（ZhiMing）；数字人角色名：豆宝。


一个真正跑在手机上的数字人：Live2D 形象 + 表情 + 口型 + 语音 + 聊天。开在手机 Chrome 里，服务器和语音合成都在这台手机的 Ubuntu 环境里，不依赖云端视频生成。

## 打开方式

```sh
cd /root/workspace/digital-human
sh start.sh
```

然后手机 Chrome 打开 **http://127.0.0.1:8100**，点「唤醒」就可以对话了。

**放到手机桌面（像 App 一样）**：Chrome 打开这个地址 → 右上角菜单 →「添加到主屏幕」或「安装应用」→ 桌面出现「豆宝」图标，点开是全屏、没有地址栏。
注意：服务必须开着（手机重启后要重新 `sh start.sh`）。

停止：`kill $(cat data/server.pid)`

| 能力 | 实现 |

| 待机 | 呼吸、眨眼、4 套待机动作轮播 |
| 表情 | 6 个表情：开心 / 难过 / 惊讶 / 生气 / 害羞 / 平静，按钮或聊天自动触发 |
| 口型 | 语音播放时实时分析音量，驱动嘴张开，说完自动闭嘴 |
| 视线/头部 | 跟着手指/鼠标轻微转头，身体有细微摆动 |
| 点按互动 | 点她有随机动作，偶尔说一句吐槽 |
| 说话 | edge-tts 中文合成（晓晓/云希/云扬/晓伊），可调语速 |
| 字幕 | 逐句高亮，跟着语音走 |
| 聊天 | 有 DeepSeek Key 走真模型；没有就用内置段子库兜底 |
| 听懂你说话 | 本机 SenseVoice 离线识别：点「说话」→ 说完点「说完了」→ 自动转文字并回复 |
| 语言 | 底部「中文」按钮循环切换 中文 → 日本語 → English，语音、回复、笑话、开场白都跟着换 |

## 设置

页面底部「设置」：

- 音色、语速
- **大脑**：`DeepSeek 官方 API`（填 API Key），或 `本机/自定义 OpenAI 兼容接口`（填接口地址、模型名，指向本机跑的模型服务）
- Key 只存在浏览器 localStorage，请求时才发给本机服务，不落盘
- 什么都没填也能讲笑话、换表情、被点

## 语音识别

点「说话」开始录音，说完再点一次（按钮会变成「说完了」）。识别在本机做，用的是 DSH App 自带的 SenseVoice 模型（`~/.dsh/speech-to-text/sensevoice`），不需要联网；第一次会请求麦克风权限。

## 长期记忆 / 情绪 / 自传（数字生命基础）

- **记忆**：`memory_store.py`，SQLite + 本地 `embeddinggemma-300m`（768 维）语义检索；对话自动入库，回答前检索 top-4 注入上下文；重要事实高权重，按年龄衰减、超量自动清理
- **情绪**：`mood.py`，持久化「愉悦/兴奋/精力/无聊/亲近」；随对话、场景、时间演化，注入模型提示词，并影响闲置时的表情
- **自传/日记**：每天 23 点后自动用本地模型写一句日记，追加到 `data/self.md`；下次对话把最近日记和重要事实作为"自传"带进上下文
- **主动性**：闲置 3 分钟后她会自己找话题（内容由当前心情和记忆决定，20 分钟冷却）
- 数据文件：`data/memory.db`、`data/mood.json`、`data/self.md`

## 大脑来源（默认：DSH 账号，免 API Key）

1. **DSH 账号（默认）**：直接读本机引擎的登录凭据 `~/.dsh/.credentials.yaml`，用 `x-dsh-auth-token` 调 `api.deepseek.com`——和 App 里同一账号，不需要你填 Key。凭据 30 秒缓存一次，退出登录/失效时自动回退
2. **本地模型**：`127.0.0.1:8181`（Qwen3-0.6B / R1-1.5B，慢但离线）
3. **DeepSeek API Key**：自己填 Key 走官方接口
4. **自定义 OpenAI 兼容接口**

注意：账号模式是"共用登录账号直调模型"，不是复用 App 内 agent 的会话和工具（那需要引擎启动令牌，外部拿不到）。数字人自己的记忆、情绪、自传存在本地。

## 本地模型大脑 + 感知循环

`/root/workspace/local-brain/` 用 `node-llama-cpp` 的 arm64 预编译包在本机跑 GGUF 模型，对数字人暴露一个 OpenAI 兼容接口（默认 `http://127.0.0.1:8181/v1`）：

```sh
sh /root/workspace/local-brain/start-llm.sh          # 启动（默认 Qwen3-0.6B）
cd /root/workspace/local-brain
node llm-server.mjs --name r1-1.5b --model "/sdcard/模型文件/DeepSeek-R1-Distill-Qwen-1.5B-Q4_K_M.gguf"
```

本机实测（骁龙 8 Elite Gen 5，纯 CPU）：

| 模型 | 体积 | 每句耗时 | 结果 |
|---|---|---|---|
| Qwen2.5-0.5B | 380M | 0.8–2.3s | 能用，比较笨 |
| **Qwen3-0.6B（默认）** | 463M | 0.8–4.5s | 对话最自然，JSON 稳定 |
| DeepSeek-R1-1.5B | 1.1G | 2–3s | 格式稳定，偶尔跑题、复读 |
| MiniCPM5-1B | 657M | — | 当前接法输出为空（对话模板不兼容） |
| Qwen3.5-0.8B | 495M | — | 输出为空 |

循环链路：

```
环境事件（电量/网络/回来/深夜/外部注入）
      ↓
场景反应 → 更新状态（表情、动作、最近场景、时间）
      ↓  POST /api/state + 聊天请求携带 state
本地模型（JSON 约束）：{"reply":"台词","emotion":"...","gesture":"..."}
      ↓
数字人的模型表达式系统执行表情/动作 + TTS 说话
      ↓
说话/表情/动作再回传状态 → 下一轮
```

页面启动时会自动探测本机模型服务：在线且没手动选过大脑时，自动切到「本机模型」。设置里也可以手选。

## 活动轨迹记忆（外围神经网络记忆）

`trajectory_store.py`：页面每 10 秒把她的状态快照（表情/动作/是否说话/嘴部/头部/身体参数/心情/场景）编码成一句话，用本机 `embeddinggemma-300m` 神经网络转成 768 维向量存进 `data/trajectory.db`。

- **记忆**：相邻快照自动记「A 状态 → 之后变成 B 状态」，形成状态转移轨迹
- **检索**：对话前用当前状态做最近邻检索，把「以前的活动轨迹」注入模型上下文（日志 `traj-memory`）
- **预测**：`GET /api/trajectory/predict?expression=happy&gesture=sway` 用近邻历史预测下一步表情/动作；页面闲置 2 分钟后会按预测偶尔切换表情
- 说明：这里用的是「现成的 embedding 神经网络做联想记忆」，没有训练新网络；要"学习型"网络可以在轨迹数据上训练一个小预测器

## 环境感知与场景交互

感知层有三块：

1. **页面能感知的**：时间（深夜提醒）、电量（低电量/充电）、网络（断网/恢复）、页面切走再回来、长时间没人理（发呆）
2. **外部事件注入**：任何程序都可以往 `POST /api/event` 推事件，页面轮询 `/api/poll` 取走并反应（轮询而不是长连接，手机切后台不会丢）
   ```sh
   sh event.sh "外面下雨了"          # 默认类型 external
   sh event.sh "提醒一下" night      # 指定场景类型
   ```
3. **场景表**：每个事件映射到「表情 + 手势 + 气泡 + 可选语音」，语音只在高优先级事件里播，且跟随当前语言

| 事件 | 反应 |
|---|---|
| 电量 ≤20% / 充电 | 难过歪头 + 提醒 / 点头 + 安心 |
| 断网 / 恢复 | 安静 + 气泡 / 开心点头 |
| 切走再回来 | 开心摇摆 + 回来啦 |
| 深夜 23:00–05:00 | 害羞歪头 + 劝睡（每 90 分钟最多一次） |
| 发呆 8 分钟 | 无聊小动作 + 气泡 |
| 外部事件 | 惊讶抬眼 + 念出事件内容 |

**手机系统级感知**（其他 App 通知、前台应用、锁屏、真正的桌面悬浮宠物）网页拿不到，需要原生权限；升级路径见下。

## 已知限制（补充）

- DSH 本机 agent 目前没有对外的调用令牌，页面暂时不能直接驱动它当大脑；要么填 DeepSeek Key，要么起一个本机 OpenAI 兼容模型服务后用自定义模式接
- 识别在安静环境下更准，一两句话最合适
- 网页/PWA 读不到系统通知、前台应用、锁屏状态；要这些得走 ADB 桥（服务端定时 `dumpsys` 后推 `/api/event`）或做一个带通知监听+悬浮窗权限的原生 App
- 示例模型的动作自带日语音效，页面统一关掉了（`PIXI.live2d.config.sound = false`），只播放中文 TTS，避免双语音重叠

## 换成自己的形象

支持 Cubism 2 和 Cubism 3/4 模型：

1. 把模型目录放到 `public/models/<名字>/`（保留 `.model3.json` 或 `.model.json` 及其相对路径）
2. Cubism 2 模型：`http://127.0.0.1:8100/?model=models/<名字>/<文件>.model.json`
3. Cubism 3/4 模型：`http://127.0.0.1:8100/?runtime=cubism4&model=models/<名字>/<文件>.model3.json`

当前 `public/models/hibiki` 是 Live2D 官方示例模型（打包在 `live2d-widget-models` npm 包里，GPL-2.0 打包、原模型适用 Live2D 免费素材许可），只适合本地演示；要发布或商用请换成自己的模型并确认授权。

## 已知限制

- 语音合成是**在线**的（edge-tts → 微软语音服务），断网只能换表情不能说话
- 语音识别还没接：现在只能打字聊天；要「说话她就能听见」需要再接 ASR
- 不是原生 App，是手机本地网页；熄屏/切后台会暂停
- 手机上不跑视频数字人模型（SadTalker/Wav2Lip 这类），出成品视频仍建议走即梦对口型

## 镜像模式：这个聊天界面同步到舞台

- `GET /api/mirror?since=<seq>`：读取当前 DSH 会话最新用户/助手消息（解压 session.v4.jsonl.zstd，缓存按文件 mtime/size）
- 舞台页每 3 秒轮询，新增消息显示成气泡；助手回复会自动朗读（≤160 字、避开代码块）
- 设置面板可开关「镜像 DSH 会话」（默认开）
- 实测：能读到当前会话最新消息（seq 5466，40 条）

## 参数化与自动训练

- **威胁词典**：`data/affect_lexicon.json`（可配置/可反馈调权，来源标记 hardcoded/配置/feedback）
- **阈值参数**：`data/tunables.json`（从观测分布标定，来源可追溯）
- **UI 参数**：`data/ui_params.json`（插件轮询间隔、页面轨迹间隔等，`GET/POST /api/ui-params`）
- **自动训练**：后台循环检测真实反馈增量 ≥5 条就重训威胁分类器（实测 15→20 条触发，版本 2）
- **语义分类器**：`classifier.py`，embedding + 逻辑回归，关键词退为先验兜底

## 认知器官：工作记忆 / 注意闸 / 意图（`organs.py`）

- **注意闸**：外部事件先过闸，重复事件、低价值感知（电量/时段类、强度<0.3）直接过滤，不占工作记忆
- **工作记忆**：最近 20 条通过闸的高价值感知（带显著度），供当前思考使用
- **意图**：candidate/active/blocked/done 四态意图，带证据列表
- 实测：通知通过、重复通知过滤、低价值感知过滤（通过 1 / 过滤 2）；意图"想提醒你早点睡"（active，证据 23点了）
- 接口：`GET /api/organs`、`POST /api/organs/intent`、`POST /api/organs/intent/update`

## 感知采集 + 意识循环 + 三层面板

- **感知采集**：后台每 60 秒扫一次（时段/电量/空闲），变化或被手动触发时写入事件总线 `perception`；`POST /api/perception/scan` 立即扫；智能体侧可用 `digital_human_perceive` 推任意感知
- **意识循环**：每 30 秒一次心跳（`/api/consciousness` 的 ticks），开机对比上次活动时间，中断 >10 分钟记一条"我睡了大约 X 分钟，刚醒来"到 `data/life_log.jsonl`
- **三层面板**：插件新增「魂·魄·体」页，魂=记忆/三观/模因/基因/一致性，魄=心情/注意力/层/巩固/自评/意识节拍，体=表情/动作/场景/重启/感知事件/清醒时长
- 实测：感知推送"现在是深夜。"；重启后睡醒叙事"我睡了大约 31 分钟，刚醒来"

## 基因与模因进化（`evolution.py`，按"基因=源代码、模因=权重"）

- **基因 = 系统源代码**：对 17 个核心文件做哈希得到基因 id，记录父代、是否变更、文件数/行数、适应度（当时基准分）；代码一改产生新基因代，旧代保留
- **模因 = 权重参数数据**：每一层权重是一个模因单元，带内容哈希、亲代（时间范围/来源层）、变异类型（沉积/巩固/主动/边界/重锚）、适应度、权重、状态（active/stale）
- **文化**（三观/风格/自述）单独记录，不算模因：有亲代链、变异方式、适应度、状态
- 实测：基因两次快照形成父子链（`13215c545457` → `d82bf4523af3`，changed true）；模因 14 条（era 4 / consolidation 3 / boundary 3 / active 2 / retrained 2）
- 接口：`GET /api/evolution`、`POST /api/evolution/code-snapshot`、`POST /api/evolution/scan`
