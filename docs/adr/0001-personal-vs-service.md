# ADR 0001：个人版与服务版双模式

## 状态

已接受（2026-11-27）

## 背景

系统目前是**个人版**：一台手机、一个用户、一份数据。
如果把产品拿出去给别人用，会变成**服务版**：多租户、多行星、API 化。

两者不是同一件事，不能用一套实现硬扛。

## 决策

1. 当前只做个人版，单行星（planet = owner）。
2. 保留三个接缝，成本极低：
   - **行星 ID**：数据路径预留 `planet_id`，现在固定 `owner`
   - **请求身份**：接口支持可选 `user`，现在默认 owner 并忽略其他
   - **存储抽象**：统一通过 `planet_dir(user)` 取路径
3. 服务版等真实需求出现再做，不提前实现多租户。

## 个人版

```
一个太阳：基础模型/API
一颗行星：owner 的层、记忆、情绪、自我内核
无认证、无计费、无隔离需求
```

## 服务版的额外要求（暂不做）

- 认证：账号 / API Key
- 隔离：A 的行星不可被 B 读取
- 配额与计费
- 审计与删除权
- 共享太阳的 GPU 集群
- 每用户卫星（LoRA/适配器）

## 行星布局（预留）

```
data/                 # 默认行星 owner（现状）
data/planets/<user>/  # 未来其他行星
data/shared/          # 小行星带：集体记忆
```

## 后果

- 现在不动数据布局，`planet_dir("owner")` 仍返回 `data/`
- 未来接认证时，只需把 `user` 解析接到认证层
- 不会因为过早多租户化而增加运维负担
